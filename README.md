# PC Consultant

**PC Consultant** — настольное приложение-консультант для подбора комплектующих персонального компьютера, реализованное на **C++17** и **Qt 6 Widgets**.

Программа последовательно задаёт пользователю вопросы о его текущей конфигурации, целях, требованиях и сценариях использования ПК. На основе ответов `Да / Нет` приложение проходит по бинарному дереву решений и приводит пользователя к итоговой рекомендации.

Проект построен с разделением логики приложения и графического интерфейса: дерево решений, состояние консультации и его валидация находятся в отдельном Core-слое, а Qt используется преимущественно для GUI, ресурсов и пользовательских настроек.

---

## Возможности

- интерактивный подбор комплектующих ПК;
- бинарное дерево решений;
- **57 вопросов и 35 итоговых выходов**;
- переходы между вопросами с ответами **«Да» / «Нет»**;
- возможность вернуться к предыдущему вопросу;
- возможность начать консультацию заново;
- отдельное отображение итоговой рекомендации;
- история прохождения дерева;
- окно настроек приложения;
- светлая и тёмная темы оформления;
- выбор шрифта;
- выбор акцентного цвета;
- анимированные переходы между вопросами;
- сохранение пользовательских настроек между запусками;
- загрузка структуры дерева из JSON;
- автоматическая проверка целостности дерева решений при загрузке.

---

## Интерфейс

Основной интерфейс построен вокруг карточки текущего вопроса.

Пользователь отвечает на вопрос, после чего приложение автоматически переходит к следующему узлу дерева. Если достигнут терминальный узел, вместо нового вопроса отображается итоговая рекомендация.

В нижней части интерфейса расположена кнопка **«Настройки»**.

В настройках доступны следующие разделы:

### Внешний вид

Позволяет изменить:

- тему приложения;
- используемый шрифт;
- акцентный цвет интерфейса.

Поддерживаемые акцентные цвета:

- синий;
- зелёный;
- красный;
- жёлтый.

### История ответов

Показывает путь, который пользователь прошёл по дереву решений.

История визуально оформлена в виде вертикального дерева, напоминающего вывод `git log`, что позволяет быстро увидеть последовательность вопросов и выбранных ответов.

## Архитектура

Проект разделён на несколько логических частей:

```text
PC Consultant
│
├── Core
│   ├── DecisionNode
│   ├── DecisionTree
│   ├── TreeLoader
│   ├── TreeValidator
│   └── ConsultationSession
│
├── UI
│   ├── MainWindow
│   └── SettingsDialog
│
├── Settings
│   ├── AppSettings
│   └── ThemeManager
│
└── Resources
    ├── consultant_tree.json
    ├── icons
    └── Qt Resources
```

### Core

Core содержит основную бизнес-логику приложения и максимально отделён от GUI.

#### `DecisionNode`

Представляет отдельный узел дерева.

Узел может быть:

- вопросом;
- конечным результатом.

Для вопроса хранятся ссылки на следующие узлы для ответов `Да` и `Нет`.

#### `DecisionTree`

Хранит полную структуру дерева решений и предоставляет доступ к узлам по их идентификаторам.

#### `TreeLoader`

Загружает дерево решений из JSON-данных, встроенных в ресурсы приложения.

#### `TreeValidator`

Проверяет корректность дерева перед началом работы.

В частности, контролируется:

- наличие корневого узла;
- существование целевых узлов;
- наличие двух переходов у вопросов;
- отсутствие переходов у терминальных результатов;
- корректность структуры дерева.

#### `ConsultationSession`

Хранит состояние текущей консультации:

- текущий узел;
- выбранные ответы;
- историю переходов;
- возможность возврата назад;
- перезапуск консультации.

GUI не определяет самостоятельно, какой вопрос должен быть показан следующим — этим занимается Core.

---

## Дерево решений

Логика консультации хранится отдельно от исходного кода в JSON.

Пример структуры:

```json
{
    "root": "Q01",
    "questions": {
        "Q01": {
            "text": "Вы выбираете компонент для уже работающего ПК?",
            "yes": "Q02",
            "no": "Q48"
        }
    },
    "results": {
        "O_GPU1": {
            "text": "Итоговая рекомендация..."
        }
    }
}
```

JSON подключается через **Qt Resource System**, поэтому после сборки дополнительный файл с деревом рядом с `.exe` не требуется.

# Сборка проекта

## Требования

Для самостоятельной сборки необходимо установить:

1. **CMake**
2. **Qt 6.11.2**
3. компонент Qt **MSVC2022 64-bit**
4. **Visual Studio 2026** с установленным workload:

```text
Desktop development with C++
```

Должны быть доступны:

- MSVC toolchain;
- Windows SDK;
- CMake;
- x64 build tools.

В используемой конфигурации Qt находится в:

```text
C:\Qt\6.11.2\msvc2022_64
```

---

## Сборка Release

Откройте **Developer Command Prompt for Visual Studio** либо обычный терминал с доступным MSVC toolchain.

Перейдите в каталог проекта:

```powershell
cd C:\Projs\pc_consult
```

Создайте отдельную Release-конфигурацию:

```powershell
cmake -S . -B build-release `
    -G "Visual Studio 18 2026" `
    -A x64 `
    -DCMAKE_PREFIX_PATH="C:/Qt/6.11.2/msvc2022_64" `
    -DBUILD_TESTING=OFF
```

После успешной конфигурации выполните сборку:

```powershell
cmake --build build-release --config Release --target PCConsultant
```

Готовый исполняемый файл будет находиться здесь:

```text
build-release\Release\PCConsultant.exe
```

---

## Запуск после сборки

Запустить приложение непосредственно из каталога сборки можно командой:

```powershell
.\build-release\Release\PCConsultant.exe
```

При запуске из Qt Creator необходимые библиотеки Qt обычно доступны через настроенное окружение Qt.

Для запуска приложения на другом компьютере необходимо предварительно выполнить deployment Qt-библиотек.

# Deployment

Для создания автономной папки приложения используется `windeployqt`.

Из корня проекта создайте каталог:

```powershell
mkdir deploy
```

Скопируйте туда Release-версию приложения:

```powershell
copy .\build-release\Release\PCConsultant.exe .\deploy\
```

После этого выполните:

```powershell
C:\Qt\6.11.2\msvc2022_64\bin\windeployqt.exe `
    --release `
    --compiler-runtime `
    .\deploy\PCConsultant.exe
```

После выполнения команды каталог `deploy` будет содержать:

```text
deploy\
├── PCConsultant.exe
├── Qt6Core.dll
├── Qt6Gui.dll
├── Qt6Widgets.dll
├── platforms\
│   └── qwindows.dll
├── styles\
├── imageformats\
└── ...
```

Состав дополнительных каталогов может отличаться в зависимости от используемых Qt-модулей.

> **Важно:** распространять необходимо именно **Release-сборку**.

Debug-версия приложения использует библиотеки вида:

```text
Qt6Cored.dll
Qt6Guid.dll
Qt6Widgetsd.dll
```

Они не предназначены для обычного распространения приложения.

У Release-версии используются библиотеки без суффикса `d`:

```text
Qt6Core.dll
Qt6Gui.dll
Qt6Widgets.dll
```

# Чистая повторная сборка

Если необходимо полностью пересоздать Release-сборку:

```powershell
cd C:\Projs\pc_consult

Remove-Item build-release -Recurse -Force -ErrorAction SilentlyContinue

cmake -S . -B build-release `
    -G "Visual Studio 18 2026" `
    -A x64 `
    -DCMAKE_PREFIX_PATH="C:/Qt/6.11.2/msvc2022_64" `
    -DBUILD_TESTING=OFF

cmake --build build-release --config Release --target PCConsultant
```

Для повторного создания deployment-папки:

```powershell
Remove-Item deploy -Recurse -Force -ErrorAction SilentlyContinue
New-Item -ItemType Directory deploy

Copy-Item `
    .\build-release\Release\PCConsultant.exe `
    .\deploy\PCConsultant.exe

C:\Qt\6.11.2\msvc2022_64\bin\windeployqt.exe `
    --release `
    --compiler-runtime `
    .\deploy\PCConsultant.exe
```

После этого `deploy` содержит готовую к распространению версию приложения.

# Сборка через Qt Creator

Проект также можно открыть непосредственно через Qt Creator.

1. Откройте корневой `CMakeLists.txt`.
2. Выберите Kit:

```text
Desktop Qt 6.11.2 MSVC2022 64bit
```

3. Выполните Configure Project.
4. В качестве конфигурации выберите:

```text
Release
```

5. Соберите target:

```text
PCConsultant
```

Для итогового релиза рекомендуется использовать отдельный каталог `build-release`, чтобы Debug- и Release-файлы не смешивались.

# Тестирование

Архитектура проекта позволяет тестировать логику дерева отдельно от пользовательского интерфейса.

Основными объектами тестирования являются:

- загрузка дерева;
- валидация дерева;
- переход по ответу `Да`;
- переход по ответу `Нет`;
- возврат к предыдущему узлу;
- перезапуск консультации;
- достижение терминального результата;
- корректность ссылок между узлами.

Для production-сборки тесты можно отключить:

```text
-DBUILD_TESTING=OFF
```

Это позволяет собрать только само приложение без тестовых executable-файлов.

# Принцип работы

Общий поток выполнения приложения:

```text
Запуск программы
       │
       ▼
Загрузка consultant_tree.json
       │
       ▼
Создание DecisionTree
       │
       ▼
Проверка TreeValidator
       │
       ▼
Создание ConsultationSession
       │
       ▼
Отображение первого вопроса
       │
       ▼
     Да / Нет
       │
       ▼
Переход к следующему узлу
       │
       ├───────────────┐
       ▼               ▼
   Новый вопрос    Результат
       │               │
       └───────┐       │
               ▼       ▼
          Продолжение / завершение
```

Каждый вопрос имеет ровно два возможных перехода:

```text
          ┌── Да  ──► следующий узел
Вопрос ───┤
          └── Нет ──► следующий узел
```

Итоговые узлы являются терминальными и не содержат дальнейших переходов.

# Цель проекта

PC Consultant демонстрирует применение классического алгоритма ветвления для построения экспертной системы подбора компьютерных комплектующих.

Основная идея проекта — отделить знания предметной области от программного интерфейса:

```text
Данные дерева
      ↓
Decision Tree
      ↓
Consultation Session
      ↓
Qt GUI
      ↓
Пользователь
```

Благодаря этому дерево решений можно расширять и изменять независимо от основной логики пользовательского интерфейса.
